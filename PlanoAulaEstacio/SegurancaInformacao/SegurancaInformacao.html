1. Visão geral

Segurança da Informação é o conjunto de práticas, tecnologias e controles usados para proteger dados contra acesso indevido, alteração, destruição, perda ou indisponibilidade. As funções hash aparecem principalmente quando precisamos comprovar que uma informação permaneceu íntegra.

Confidencialidade

Quem pode ver?

Impede que pessoas não autorizadas tenham acesso ao conteúdo.

Integridade

O conteúdo foi alterado?

Permite identificar mudanças acidentais ou maliciosas nos dados.

Disponibilidade

O serviço está acessível?

Garante que sistemas e informações estejam disponíveis quando necessários.

Ponto-chave: hash está ligado principalmente à integridade. Criptografia está ligada principalmente à confidencialidade.

3. O que é uma função hash?

Uma função hash recebe dados de tamanho variável e produz um resumo de tamanho fixo. Esse resumo é chamado de hash, digest ou resumo criptográfico.

Entrada de qualquer tamanho → Função hash → Saída de tamanho fixo

Exemplo conceitual:

"Ola Mundo" → SHA-256 → 80693d4f85fd6dc2...

Características fundamentais

  • A mesma entrada sempre produz o mesmo hash.
  • Uma pequena mudança na entrada altera fortemente o resultado.
  • O hash possui tamanho fixo.
  • Não deve ser viável recuperar a entrada original a partir do hash.
  • Deve ser difícil encontrar duas entradas diferentes com o mesmo hash.
Não confunda: hash não é criptografia. A criptografia possui uma chave e pode ser revertida por quem tem autorização. O hash é projetado para ser unidirecional.

4. Entendendo a função hash módulo 10

No exercício, foi utilizada a função:

hash(n) = n mod 10

O operador mod retorna o resto da divisão. Quando fazemos n mod 10, basta observar o último algarismo do número.

Número Cálculo Posição hash
88 mod 108
1313 mod 103
2424 mod 104
3636 mod 106
4949 mod 109
5252 mod 102
6262 mod 102
7171 mod 101
8383 mod 103
9797 mod 107
Dica de prova: em mod 10, números com o mesmo último algarismo irão para a mesma posição.

5. O que é uma colisão?

Uma colisão ocorre quando duas entradas diferentes geram o mesmo valor hash.

hash(52) = 2 hash(62) = 2 hash(13) = 3 hash(83) = 3

Logo, os pares que colidem são:

Posição Números Situação
2 52 e 62 Colisão
3 13 e 83 Colisão
Erro comum: achar que colisão significa que o algoritmo falhou. Como o conjunto de entradas possíveis é maior que o conjunto de saídas, colisões matematicamente podem existir. A segurança exige que seja extremamente difícil encontrá-las de forma prática.

6. Propriedades de segurança das funções hash

Propriedade O que já é conhecido? Objetivo do atacante
Resistência à pré-imagem O valor hash Descobrir uma mensagem que produza aquele hash.
Resistência à segunda pré-imagem Uma mensagem específica m1 Encontrar outra mensagem m2 com o mesmo hash de m1.
Resistência à colisão Nenhuma mensagem específica Encontrar quaisquer duas mensagens diferentes com o mesmo hash.
Como identificar a segunda pré-imagem: quando o enunciado diz “dada uma mensagem m1, encontrar outra m2 diferente, com hash(m1) = hash(m2)”.

Unidirecionalidade

Significa que é fácil calcular o hash a partir da entrada, mas não deve ser computacionalmente viável fazer o caminho inverso.

Mensagem → Hash (fácil) Hash → Mensagem original (computacionalmente inviável)

3. Receptor Calcula o hash novamente e compara.
Comparação Interpretação
Hash enviado = Hash calculado O conteúdo recebido corresponde ao conteúdo original.
Hash enviado ≠ Hash calculado O conteúdo foi alterado, corrompido ou substituído.
Limitação importante: o hash sozinho detecta alteração, mas não confirma necessariamente quem enviou a mensagem. Para autenticação e não repúdio, utilizam-se mecanismos como HMAC e assinatura digital.

8. MD5, SHA-1 e SHA-2

Algoritmo Tamanho comum do hash Situação Uso recomendado
MD5 128 bits Inseguro contra colisões Apenas compatibilidade legada ou verificação não criptográfica.
SHA-1 160 bits Inseguro contra colisões Não recomendado para segurança.
SHA-256 256 bits Amplamente utilizado Integridade, assinaturas e aplicações modernas.
SHA-512 512 bits Amplamente utilizado Aplicações que adotam a família SHA-2.
Correção importante para prova: SHA-1 não utiliza 256 bits. Ele produz um resumo de 160 bits. A família SHA-2 inclui variantes como SHA-224, SHA-256, SHA-384 e SHA-512.

9. Uso de hash no armazenamento de senhas

Senhas não devem ser armazenadas em texto puro. O sistema deve armazenar um valor derivado da senha, utilizando algoritmos próprios para esse objetivo.

Usuário digita a senha ↓ Algoritmo de derivação de senha + salt ↓ Valor armazenado no banco de dados

Por que não usar somente SHA-256?

SHA-256 é rápido. Essa velocidade é útil para integridade, mas também facilita tentativas massivas de adivinhação de senhas. Para senhas, preferem-se algoritmos deliberadamente mais lentos e ajustáveis.

Recomendados

Algoritmos para senhas

Argon2, bcrypt, scrypt e PBKDF2.

Atenção

Salt

Valor aleatório adicionado antes do processamento para dificultar ataques com tabelas pré-calculadas.

10. Dificuldades identificadas nas atividades

1. Entender o operador módulo

A dificuldade principal foi perceber que n mod 10 representa o resto da divisão por 10. Para resolver rapidamente, observe o último algarismo.

2. Diferenciar colisão e segunda pré-imagem

Em colisão, busca-se qualquer par de mensagens. Na segunda pré-imagem, uma mensagem inicial já foi fornecida e procura-se outra com o mesmo hash.

3. Confundir hash com criptografia

Hash não serve para esconder e depois recuperar o conteúdo. Criptografia é reversível mediante chave; hash é unidirecional.

4. Associar hash à confidencialidade

A finalidade mais direta do hash é integridade. A confidencialidade depende de criptografia e controle de acesso.

5. Interpretar afirmações imprecisas

Algumas questões simplificam conceitos, como dizer que SHA-2 “utiliza 512 bits”. Tecnicamente, SHA-2 é uma família com diferentes tamanhos. Em prova, analise o contexto, mas mantenha o conceito correto.

6. Entender quando o laboratório terminou

A simulação pode permanecer parada após o envio porque está apenas demonstrando o resultado. A conclusão costuma ocorrer depois de comparar os hashes, testar uma alteração na mensagem e retornar ao ambiente virtual da disciplina.

11. Roteiro prático para o laboratório de hash

  1. Selecione o algoritmo SHA-2 no simulador.
  2. Digite uma mensagem simples, como Ola Mundo.
  3. Anote ou observe o hash mostrado no computador de origem.
  4. Clique em Enviar.
  5. Compare o hash exibido no computador de destino.
  6. Confirme que os hashes são iguais quando a mensagem não é alterada.
  7. Exclua a mensagem no destino, se necessário.
  8. Altere apenas um caractere, por exemplo: Ola Mundo!.
  9. Envie novamente e observe que o hash mudou completamente.
  10. Registre a conclusão: pequenas mudanças produzem resumos muito diferentes.
Resultado esperado: o laboratório demonstra determinismo, integridade e efeito avalanche.

12. Revisão rápida para prova

O que é hash?

Transformação de dados variáveis em um resumo de tamanho fixo.

Resposta-chave: algoritmo unidirecional.

Qual princípio é verificado?

A comparação de hashes detecta mudanças em dados.

Resposta-chave: integridade.

O que é colisão?

Duas entradas diferentes produzem o mesmo hash.

Exemplo: 52 e 62 em mod 10.

O hash pode ser revertido?

Uma função hash criptográfica deve ser resistente à pré-imagem.

Resposta-chave: não deve ser viável.

SHA-1 ainda é seguro?

Não. Existem ataques de colisão conhecidos.

Prefira algoritmos modernos.

Como armazenar senhas?

Com algoritmo próprio para senhas e salt.

Exemplos: Argon2 ou bcrypt.

HASH ├── Entrada variável ├── Saída fixa ├── Unidirecional ├── Verifica integridade ├── Pode haver colisão ├── Efeito avalanche ├── SHA-256 / SHA-512 └── Senhas: Argon2, bcrypt, scrypt ou PBKDF2

13. Entendendo a Diferença entre Hash Mod 10 e Hash Criptográfico (SHA-256)

Durante o estudo sobre funções hash, é comum surgir a dúvida sobre a relação entre o Hash Mod 10, utilizado em Estruturas de Dados, e os algoritmos modernos de segurança, como o SHA-256. Embora ambos sejam chamados de "hash", eles possuem objetivos completamente diferentes.

Hash Mod 10

O Hash Mod 10 é utilizado apenas para determinar a posição onde um dado será armazenado em uma tabela hash. Nesse caso, o valor de entrada (chave) já existe e a função hash apenas calcula: 

Hash = Chave mod 10

Exemplo: 

      52 mod 10 = 2

      Hash = 2
      Posição da tabela = 2

O objetivo é distribuir os registros entre as posições da tabela para facilitar a localização e acelerar as consultas. Como existem apenas 10 posições (0 a 9), diferentes chaves podem gerar o mesmo resultado, ocasionando uma colisão.

Hash Criptográfico (SHA-256)

Diferentemente do Hash Mod 10, o SHA-256 não utiliza uma chave numérica nem realiza uma simples divisão. O algoritmo lê todo o conteúdo do arquivo, byte por byte, independentemente de seu tipo (TXT, PDF, JPG, MP4, ZIP, EXE etc.).

Em arquivos de texto, os caracteres são representados por bytes (ASCII ou UTF-8). Em imagens, vídeos e documentos, o algoritmo também trabalha apenas com bytes, sem interpretar o tipo do arquivo.

Esses bytes são processados em blocos de 512 bits (64 bytes), passando por diversas operações matemáticas, como rotações de bits, operações XOR, funções booleanas e somas módulo 2³², produzindo ao final um resumo criptográfico de 256 bits.

O tamanho do arquivo influencia?

Não. Um dos principais conceitos do SHA-256 é que o tamanho do hash permanece sempre o mesmo, independentemente do tamanho do arquivo.

Arquivo Tamanho SHA-256
Olá.txt 3 bytes 256 bits (64 caracteres hexadecimais)
Livro.pdf 15 MB 256 bits (64 caracteres hexadecimais)
Filme.mp4 50 GB 256 bits (64 caracteres hexadecimais)

Portanto, um arquivo de poucos bytes e outro com dezenas de gigabytes produzem hashes exatamente do mesmo tamanho.

Efeito Avalanche

Uma das características mais importantes dos algoritmos criptográficos é o chamado Efeito Avalanche. Alterar apenas um único byte do arquivo é suficiente para gerar um hash completamente diferente, tornando praticamente impossível identificar qualquer semelhança entre os dois resultados.

Resumo

Hash Mod 10 SHA-256
Usado em Estruturas de Dados. Usado em Segurança da Informação.
Recebe uma chave numérica. Recebe qualquer arquivo ou sequência de bytes.
Calcula a posição de armazenamento. Calcula um resumo criptográfico.
Utiliza operações simples, como módulo. Utiliza centenas de operações matemáticas complexas.
Permite colisões com facilidade. Colisões são extremamente improváveis.
Não possui finalidade criptográfica. Garante integridade e autenticação dos dados.
Conclusão: O Hash Mod 10 é uma ferramenta didática utilizada para compreender o funcionamento das tabelas hash e das estruturas de dados. Já o SHA-256 é um algoritmo criptográfico moderno que transforma qualquer sequência de bytes em um resumo de tamanho fixo (256 bits), permitindo verificar a integridade de arquivos e detectar qualquer alteração em seu conteúdo, mesmo que apenas um único byte seja modificado.
