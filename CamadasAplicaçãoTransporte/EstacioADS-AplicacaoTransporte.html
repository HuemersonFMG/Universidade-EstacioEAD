Camadas de Aplicação e Transporte

Manual de apoio ao curso de Análise e Desenvolvimento de Sistemas — Estácio. Resumo sobre arquiteturas de aplicação, cliente-servidor, servidores, MTBF, parsers e camada de transporte.

1. Visão geral

Em redes de computadores, a comunicação é organizada em camadas. Cada camada utiliza os serviços da camada inferior e oferece serviços à camada superior.

Ideia principal: a camada de aplicação é a mais próxima do usuário e dos softwares; a camada de transporte garante a comunicação lógica entre processos de diferentes dispositivos.

Quando acessamos um site, usamos uma aplicação web. Essa aplicação utiliza protocolos da camada de aplicação, como HTTP ou HTTPS, e normalmente depende da camada de transporte, como TCP ou UDP.

2. Camada de Aplicação

O software de aplicação, também chamado de software aplicativo, é a interface entre o usuário e o sistema. É por meio dele que o usuário acessa serviços, envia informações, consulta dados e interage com recursos disponíveis em uma rede.

No modelo OSI, a camada de aplicação é a camada de mais alto nível. Ela realiza a interface com os usuários e com os programas que precisam se comunicar pela rede.

Exemplos de serviços e protocolos de aplicação

Serviço Protocolo / Tecnologia Função
Web HTTP / HTTPS Transferência de páginas e dados entre navegador e servidor web.
E-mail SMTP, POP3, IMAP Envio e recebimento de mensagens eletrônicas.
Resolução de nomes DNS Converte nomes de domínio em endereços IP.
Transferência de arquivos FTP / SFTP Envio e recebimento de arquivos pela rede.
Banco de dados SQL + protocolo do SGBD Consulta, alteração e gerenciamento de dados armazenados.

3. Arquiteturas de aplicação

Antes de desenvolver uma aplicação em rede, não basta conhecer a linguagem de programação. É necessário definir qual será a arquitetura da aplicação, ou seja, como os componentes irão se comunicar e dividir responsabilidades.

Cliente-Servidor

Um ou mais clientes solicitam serviços a um servidor central. É muito usada em aplicações web, sistemas corporativos, APIs e bancos de dados.

Peer-to-Peer (P2P)

Cada nó pode atuar como cliente e servidor ao mesmo tempo, compartilhando dados diretamente com outros participantes da rede.

Três Camadas

Divide a aplicação em interface, regra de negócio e banco de dados. É comum em sistemas empresariais e aplicações web.

Microsserviços

A aplicação é dividida em pequenos serviços independentes, cada um com uma função específica, comunicando-se por APIs ou mensageria.

Importante: a arquitetura define a organização da aplicação. O protocolo define as regras de comunicação entre os componentes.

4. Arquitetura Cliente-Servidor

Na arquitetura cliente-servidor, existem pelo menos duas entidades: um cliente e um servidor. O cliente solicita um serviço, enquanto o servidor aguarda requisições, processa os dados recebidos e retorna uma resposta.

Exemplo com aplicação web

Navegador do usuário → Requisição HTTP → Servidor Web → Processamento → Resposta HTTP → Página exibida

Quando um cliente precisa de um serviço, ele monta uma mensagem contendo a solicitação e, muitas vezes, dados que devem ser processados pelo servidor. Essa mensagem é enviada por intermédio de um sistema de comunicação, como a Internet.

5. Funcionamento do servidor

O servidor normalmente se comporta de forma passiva: ele fica aguardando solicitações dos clientes. Quando uma requisição chega, o servidor processa a mensagem e envia uma resposta contendo o resultado do processamento.

Quando chega uma solicitação, o servidor pode:

  • Atender imediatamente, caso esteja ocioso.
  • Gerar um processo-filho para atender a solicitação.
  • Criar uma thread para esse atendimento.
  • Enfileirar a solicitação para ser atendida mais tarde.
Estratégia Descrição Exemplo prático
Atendimento imediato O servidor processa a solicitação assim que ela chega. Uma API simples respondendo uma consulta leve.
Processo-filho O servidor cria outro processo para lidar com a solicitação. Serviços que isolam cada execução em processos separados.
Thread O servidor cria ou utiliza uma thread para atender a requisição. Servidores web lidando com várias conexões simultâneas.
Fila A solicitação é colocada em uma fila para ser processada depois. Envio de e-mails, geração de relatórios ou processamento assíncrono.
Aplicação web: sites, APIs e sistemas online utilizam esse modelo. O navegador atua como cliente, e o servidor web ou API processa as requisições.

6. MTBF e recursos redundantes em servidores

Servidores desempenham funções críticas em uma rede. Por isso, existem equipamentos apropriados para ambientes corporativos, com maior confiabilidade, maior durabilidade e recursos redundantes.

O que significa MTBF?

MTBF significa Mean Time Between Failures, ou Tempo Médio Entre Falhas. É uma métrica estatística usada para indicar a confiabilidade de um equipamento.

Quanto maior o MTBF, maior tende a ser a confiabilidade do equipamento. Isso não garante que o equipamento nunca falhará, mas indica que ele foi projetado para operar por longos períodos com baixa probabilidade de falha.
  • Fontes de alimentação redundantes.
  • Discos em RAID.
  • Múltiplas placas de rede.
  • Ventoinhas redundantes.
  • Nobreaks e geradores.

7. Um processo pode atuar como cliente e servidor ao mesmo tempo

A classificação de cliente ou servidor não depende apenas do equipamento físico, mas principalmente do papel desempenhado pelo software naquele momento.

Exemplo: um servidor Node.js pode ser servidor para o navegador do usuário e, ao mesmo tempo, cliente de um banco de dados ou de uma API externa.
Navegador → Servidor Node.js → Banco de Dados / API Externa
Elemento Papel desempenhado
Navegador Cliente do servidor web.
Servidor Node.js Servidor para o navegador e cliente do banco/API.
Banco de Dados Servidor para a aplicação Node.js.

8. Linguagens da Camada de Aplicação e os Parsers de Software

Tecnologias como HTML5, CSS, JavaScript e SQL não são protocolos da pilha TCP/IP. Elas são linguagens ou tecnologias utilizadas por softwares da camada de aplicação.

Um arquivo .html ou .sql é apenas texto gravado no disco. Quem entende a estrutura da linguagem é o parser, componente implementado dentro do software responsável por interpretar aquele conteúdo.

HTML5

Interpretado pelo parser HTML do navegador, como Chrome, Edge ou Firefox.

SQL

Interpretado pelo parser SQL do banco de dados, como Oracle, PostgreSQL ou MySQL.

JavaScript

Interpretado/executado por motores como o V8, presente no Chrome e no Node.js.

HTTP Desenvolvedores de navegadores e servidores web
HTML Parser Desenvolvedores de navegadores
SQL Parser Desenvolvedores de bancos de dados
DNS Desenvolvedores de servidores DNS

9. Protocolos da Camada de Aplicação

É na camada de aplicação que são executados os processos dos usuários, como navegador, cliente de e-mail, aplicativo, API ou sistema corporativo.

Para que uma aplicação em um computador troque dados com outra aplicação em outro computador, é necessário existir um protocolo de aplicação.

Definição prática: um protocolo da camada de aplicação define como processos de aplicações diferentes, em sistemas finais diferentes, trocam mensagens pela rede.

O que um protocolo de aplicação define?

Item Explicação Exemplo
Tipos de mensagens Define quais mensagens podem ser trocadas. Requisição e resposta HTTP.
Sintaxe Define formato, campos e separadores da mensagem. Cabeçalhos HTTP, corpo JSON, comandos SMTP.
Semântica Define o significado dos campos. 200 = sucesso; 404 = não encontrado.
Regras Define quando enviar, responder e tratar erros. Cliente envia GET; servidor responde HTML ou JSON.

Exemplo com HTTP

Navegador → GET /index.html → Servidor Web → 200 OK + HTML

O algoritmo da aplicação define o funcionamento local do sistema; o protocolo define como ele conversa com outro sistema pela rede.

10. Serviços de E-mail: SMTP, POP3 e IMAP

O serviço de e-mail é um exemplo clássico de aplicação em rede. Ele usa protocolos diferentes para envio e recebimento.

Protocolo Função Uso prático
SMTP Envio de e-mails. Envia mensagens do cliente ao servidor e entre servidores.
POP3 Recebimento com foco em baixar mensagens. Baixa e-mails para o dispositivo, podendo remover do servidor.
IMAP Recebimento e sincronização. Mantém mensagens no servidor e sincroniza vários dispositivos.
Para lembrar: SMTP envia. POP3 e IMAP recebem. IMAP é mais comum quando usamos e-mail em celular, notebook e webmail ao mesmo tempo.

11. API, Protocolos e RFCs

Uma API não é necessariamente um protocolo. Ela normalmente usa protocolos, como HTTP ou HTTPS, para expor serviços e trocar dados.

Conceito O que é Exemplo
API Conjunto de endpoints, funções e regras de negócio. /api/pedido, /api/login.
Protocolo Regras padronizadas de comunicação. HTTP, HTTPS, TCP, IP, DNS.
Formato de dados Forma de representar informações. JSON, XML, HTML.
Navegador → HTTPS → API Node.js → JSON → Resposta ao Cliente

Criar um protocolo próprio seria mais complexo, pois exigiria definir formato de mensagem, autenticação, erros, timeout, retry, parser, documentação e versionamento.

O que são RFCs?

RFC significa Request For Comments. São documentos técnicos que especificam protocolos e padrões públicos da Internet.

RFC Protocolo / Assunto
RFC 791 IP
RFC 793 TCP
RFC 768 UDP
RFC 1035 DNS
RFC 5321 SMTP
Resumo: as RFCs permitem que diferentes desenvolvedores criem navegadores, servidores, sistemas operacionais e roteadores compatíveis entre si.

12. Camada de Transporte

A camada de transporte é responsável por carregar mensagens da camada de aplicação entre processos que rodam em sistemas finais. Na Internet, seus principais protocolos são TCP e UDP.

Protocolo Características Exemplos de uso
TCP Orientado à conexão, confiável, com controle de fluxo, controle de erros e retransmissão. HTTP/HTTPS, FTP, SSH, e-mail.
UDP Não orientado à conexão, mais simples, mais rápido e sem garantia de entrega. DNS, VoIP, streaming, jogos online.

Multiplexação

A multiplexação permite que várias aplicações usem a rede ao mesmo tempo. A camada de transporte identifica cada processo por meio de portas.

Aplicações diferentes → Portas TCP/UDP → Segmentos/Datagramas → Camada de Internet (IP)

No TCP, a PDU é chamada de segmento. No UDP, muitas vezes é chamada de datagrama UDP.

14. Correio Eletrônico, DNS e Curiosidades Práticas

O correio eletrônico é um serviço da camada de aplicação usado para enviar, receber e armazenar mensagens entre usuários na Internet.

Protocolos usados no e-mail

Protocolo Função Exemplo prático
SMTP Responsável pelo envio de e-mails. Quando você envia uma mensagem pelo Gmail, Outlook ou outro serviço.
POP3 Recebe e baixa mensagens para o dispositivo local. Útil quando o e-mail é armazenado localmente em um computador.
IMAP Recebe e sincroniza mensagens mantendo-as no servidor. Ideal para acessar o mesmo e-mail no celular, notebook e navegador.
Resumo: SMTP envia. POP3 e IMAP recebem. Atualmente, o IMAP é muito usado porque mantém os e-mails sincronizados em vários dispositivos.

Serviço de nomes DNS

O DNS (Domain Name System) converte nomes de domínio legíveis por humanos em endereços IP compreendidos pelas máquinas.

www.google.com → DNS → Endereço IP → Servidor de destino
Registro DNS Função
A Associa um domínio a um endereço IPv4.
AAAA Associa um domínio a um endereço IPv6.
CNAME Cria um apelido para outro nome de domínio.
MX Indica os servidores responsáveis pelo recebimento de e-mails do domínio.
TXT Armazena informações textuais, muito usado para validações e segurança.

Curiosidade prática: W3Schools

O termo correto é W3Schools. É um site muito utilizado por estudantes e desenvolvedores para consultar exemplos de HTML, CSS, JavaScript, SQL e outras tecnologias da camada de aplicação.

Observação: o W3Schools é útil para consulta rápida e exemplos práticos, mas não substitui a documentação oficial das tecnologias.

Comandos úteis no CMD para testes de rede

Comando Função Exemplo
ipconfig Mostra informações de rede da máquina. ipconfig /all
ping Testa se um host responde na rede. ping google.com
tracert Mostra o caminho percorrido até o destino. tracert google.com
nslookup Consulta registros DNS de um domínio. nslookup google.com
netstat Lista conexões de rede ativas e portas em uso. netstat -ano
Exemplo prático: nslookup google.com → Consulta DNS → Retorna endereços IP associados ao domínio
Resumo para prática: DNS resolve nomes em IPs; SMTP envia e-mails; POP3/IMAP recebem e-mails; comandos como ping, tracert e nslookup ajudam a diagnosticar problemas reais de rede.
