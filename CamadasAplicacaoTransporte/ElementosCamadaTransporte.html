Elementos da Camada de Transporte

Manual de apoio ao curso de Análise e Desenvolvimento de Sistemas — Estácio. Conteúdo prático sobre endereçamento de processos, portas TCP/UDP, multiplexação, demultiplexação, cabeçalhos da camada de transporte e nomenclatura dos dados em cada camada.

1. Entendendo o problema

Quando um programa solicita algo a um servidor, a mensagem não deve chegar apenas ao computador de destino. Ela precisa chegar à aplicação correta dentro daquele computador.

Dúvida comum: se um servidor executa várias aplicações ao mesmo tempo, como o sistema sabe para qual aplicação entregar cada mensagem?

Essa é justamente uma das funções da camada de transporte: identificar qual processo ou aplicação deve receber os dados.

→
Site Web
Porta 80/443
Banco
Porta 1521/5432

Resumo simples: o endereço IP identifica o computador. A porta identifica a aplicação dentro desse computador.

2. Endereçamento na camada de transporte

Na camada de rede, o endereço IP indica o hospedeiro de destino. Porém, dentro desse hospedeiro podem existir vários processos ativos.

Por isso, a camada de transporte usa um endereço próprio para identificar a aplicação. Nos protocolos TCP e UDP, esse endereço é chamado de porta.

Camada Endereço usado Identifica o quê? Exemplo
Internet / Rede Endereço IP O computador ou hospedeiro na rede. 192.168.0.10
Transporte Porta TCP/UDP A aplicação ou processo dentro do computador. 443, 80, 53, 25, 3306
IP = endereço do prédio Porta = número da sala dentro do prédio

3. Como cada camada denomina os dados trocados?

Em redes, os dados recebem nomes diferentes conforme descem ou sobem pelas camadas. Esses nomes são chamados de PDU (Protocol Data Unit), ou seja, unidade de dados do protocolo.

Modelo / Camada Nome dos dados Exemplo prático
Aplicação Mensagem ou dados Requisição HTTP, e-mail, JSON, HTML.
Transporte - TCP Segmento TCP Dados da aplicação com cabeçalho TCP, portas e controle.
Transporte - UDP Datagrama UDP Dados da aplicação com cabeçalho UDP simples.
Internet / Rede - IP Pacote ou datagrama IP Segmento TCP ou datagrama UDP encapsulado com endereço IP.
Enlace Quadro ou frame Pacote IP encapsulado em Ethernet ou Wi-Fi.
Física Bits Sequência de 0s e 1s transmitida por cabo, fibra ou ondas.
Mensagem → Segmento/Datagrama → Pacote IP → Quadro → Bits
Para lembrar: a camada de transporte trabalha principalmente com segmentos TCP ou datagramas UDP.

4. Exemplo prático: acessando um site

Quando você acessa um site no navegador, como https://www.exemplo.com, o navegador precisa saber para qual servidor enviar a mensagem e em qual porta o serviço web está aguardando conexões.

Navegador → DNS descobre o IP → Conecta no IP + Porta 443 → Servidor Web responde
Elemento Exemplo Função
Nome do serviço https://www.exemplo.com Nome amigável usado pelo usuário.
Endereço IP 203.0.113.10 Identifica o servidor na rede.
Porta 443 Identifica a aplicação HTTPS dentro do servidor.
Processo Servidor Web Aplicação que recebe e responde a requisição.

5. O que são portas TCP e UDP?

Uma porta é um número usado pela camada de transporte para entregar os dados à aplicação correta.

Imagine um servidor com um único endereço IP, mas executando vários serviços:

Serviço Protocolo Porta comum Função
HTTP TCP 80 Acesso a páginas web sem criptografia.
HTTPS TCP 443 Acesso seguro a páginas e APIs.
DNS UDP/TCP 53 Resolução de nomes de domínio.
SMTP TCP 25 / 587 Envio de e-mails.
SSH TCP 22 Acesso remoto seguro a servidores.
Oracle TCP 1521 Conexão com banco de dados Oracle.
PostgreSQL TCP 5432 Conexão com banco de dados PostgreSQL.
MySQL TCP 3306 Conexão com banco de dados MySQL.
Importante: as portas comuns são convenções. Um serviço pode ser configurado em outra porta, mas isso precisa ser conhecido pelo cliente.

6. Como o cliente sabe a porta do servidor?

Para que uma aplicação envie dados corretamente, ela precisa saber qual endereço de transporte deve usar no destino. Em TCP e UDP, isso significa saber a porta.

Forma 1: portas padronizadas

Alguns serviços usam portas conhecidas há muitos anos. Assim, os usuários e os softwares já sabem qual porta utilizar.

HTTP → porta 80 HTTPS → porta 443 DNS → porta 53 SMTP → porta 25/587

Isso permite que um navegador saiba que, ao acessar um site HTTPS, normalmente deve usar a porta 443.

Forma 2: endereço informado pelo usuário ou sistema

Em alguns casos, a porta precisa ser informada manualmente ou configurada no sistema.

http://localhost:3000 IP do servidor: 10.0.0.5 Porta da API: 3000

Esse é um exemplo comum em aplicações Node.js, React, APIs locais e ambientes de teste.

7. Servidor de nomes e servidor de diretórios

Um esquema alternativo para localizar serviços é utilizar um processo especial chamado servidor de nomes ou servidor de diretórios.

A ideia é simples: em vez do cliente decorar o endereço do serviço, ele pergunta a um servidor especializado onde aquele serviço está.

Cliente
→
Servidor de Nomes
Onde está o serviço?
→
Retorna
IP + Porta

Exemplo prático com DNS

O DNS é um exemplo conhecido de sistema de nomes. Ele traduz um nome, como www.google.com, para um endereço IP.

www.google.com → DNS → endereço IP do servidor

Em alguns sistemas corporativos, também pode existir um diretório de serviços, responsável por indicar onde estão APIs, bancos, microsserviços ou servidores internos.

Resumo: servidor de nomes ou diretórios ajuda a localizar serviços sem que o cliente precise conhecer todos os endereços manualmente.

8. Multiplexação e demultiplexação

A multiplexação e a demultiplexação permitem que várias aplicações usem a rede ao mesmo tempo, mantendo a entrega correta dos dados para cada processo.

Multiplexação

Acontece no hospedeiro de origem. A camada de transporte reúne dados vindos de várias aplicações, adiciona cabeçalhos com as portas corretas e envia os segmentos para a camada de rede.

Demultiplexação

Acontece no hospedeiro de destino. A camada de transporte examina a porta de destino no cabeçalho e entrega os dados para a aplicação correta.

Resumo simples: multiplexar é juntar vários fluxos para enviar pela rede. Demultiplexar é separar o que chegou e entregar a cada aplicação correta.

9. Multiplexação na origem

No computador de origem, várias aplicações podem gerar dados ao mesmo tempo: navegador, e-mail, transferência de arquivos, chamadas de vídeo, jogos e outras.

A camada de transporte recebe essas porções de dados, identifica cada uma pela porta de origem e pela porta de destino, cria os segmentos ou datagramas e entrega tudo para a camada de rede.

Passos da multiplexação

  • Receber dados de diferentes aplicações.
  • Identificar a porta usada por cada processo.
  • Adicionar cabeçalho TCP ou UDP com portas e informações de controle.
  • Criar segmentos TCP ou datagramas UDP.
  • Passar os dados para a camada de rede/IP.
Browser + E-mail + FTP → TCP adiciona portas → Segmentos → IP → Rede

10. Demultiplexação no destino

No hospedeiro destino, a camada de transporte recebe dados vindos da camada de rede. Ela examina os campos do cabeçalho de transporte, principalmente a porta de destino, para saber qual aplicação deve receber aqueles dados.

Segmento recebido → Examina porta de destino → Entrega ao processo correto

Por exemplo, se o segmento chega com porta de destino 443, ele será entregue ao processo responsável pelo serviço HTTPS. Se chega com porta 25 ou 587, será entregue ao serviço de e-mail SMTP.

Ponto-chave: a demultiplexação é o processo de entregar os dados recebidos à porta correta, ou seja, à aplicação correta.

11. Exemplo de Eduardo usando vários programas

Imagine que Eduardo esteja usando a Internet para três atividades ao mesmo tempo:

  • Navegar na web pelo browser.
  • Acessar seu e-mail.
  • Fazer download de arquivos por um programa específico.

Todos esses programas podem usar o protocolo TCP ao mesmo tempo. Para diferenciar cada programa, o TCP utiliza portas.

Programa usado por Eduardo Porta local de origem Destino provável
Browser web 11278 Servidor web na porta 443 ou 80.
Cliente de e-mail 25786 Servidor de e-mail SMTP, IMAP ou POP3.
Transferência de arquivos 3709 Servidor de arquivos, FTP, SFTP ou serviço equivalente.
Observação: servidores normalmente usam portas conhecidas. Programas clientes costumam usar portas temporárias ou aleatórias.
Browser porta 11278 E-mail porta 25786 Arquivos porta 3709 ↓ TCP identifica cada fluxo separadamente

12. Como o TCP sabe quem é quem?

Para usar o TCP, um processo precisa se associar a uma porta. Quando um programa cliente inicia uma comunicação, o sistema operacional normalmente escolhe uma porta temporária para ele.

Quando o browser de Eduardo envia uma solicitação para um servidor web, o TCP inclui no cabeçalho informações como:

Campo Exemplo O que significa?
IP de origem 192.168.0.20 Computador de Eduardo.
Porta de origem 11278 Browser web de Eduardo.
IP de destino 203.0.113.10 Servidor web acessado.
Porta de destino 443 Serviço HTTPS do servidor.

Quando o servidor responde, ele envia a resposta de volta para o IP e porta de origem. Assim, o computador de Eduardo sabe que aquela resposta pertence ao browser, e não ao e-mail ou ao programa de transferência de arquivos.

Resposta do servidor → IP 192.168.0.20 + porta 11278 → Browser de Eduardo

13. Cabeçalhos da camada de transporte

Toda mensagem da camada de transporte carrega informações de controle em seu cabeçalho. Esse cabeçalho ajuda a entregar os dados à aplicação correta.

Entre os campos mais importantes estão a porta de origem e a porta de destino.

Campo do cabeçalho Função Exemplo
Porta de origem Identifica a aplicação que enviou os dados. 11278
Porta de destino Identifica a aplicação que deve receber os dados. 443
Controle de sequência Ajuda a ordenar os dados no TCP. Segmento 1, 2, 3...
Checksum Ajuda a detectar erros nos dados. Verificação de integridade.
Flags de controle Usadas pelo TCP para controlar conexão. SYN, ACK, FIN.
Dados da Aplicação ↓ Cabeçalho TCP/UDP + Dados ↓ Segmento TCP ou Datagrama UDP

14. Exemplo completo: navegador acessando uma API

Vamos imaginar seu navegador acessando uma API em Node.js.

Navegador → HTTPS → IP do servidor → Porta 443 → API Node.js → Resposta JSON
Etapa O que acontece?
1. Usuário acessa o sistema O navegador recebe uma URL, como https://meusistema.com/api/pedido.
2. DNS resolve o nome O domínio é convertido para o endereço IP do servidor.
3. Transporte usa a porta Por ser HTTPS, o navegador tenta acessar a porta 443.
4. Servidor recebe a requisição A mensagem chega ao processo correto que está escutando naquela porta.
5. API responde A aplicação processa a requisição e retorna dados, normalmente em JSON.
Ponto-chave: sem portas, o servidor até poderia receber os pacotes, mas não saberia qual aplicação deveria processá-los.

15. Analogia prática

Uma forma simples de entender é comparar com um prédio comercial:

Rede Analogia
Endereço IP Endereço do prédio.
Porta TCP/UDP Número da sala dentro do prédio.
Aplicação Empresa que trabalha naquela sala.
Mensagem Correspondência enviada para uma empresa específica.
Multiplexação Várias empresas enviando correspondências pelo mesmo prédio.
Demultiplexação A portaria separando as correspondências e entregando para cada sala correta.
IP leva até o prédio. Porta leva até a sala correta. Demultiplexação entrega para a empresa correta.
